## 1. 执行摘要

Codex-O 是一个本机优先的 Codex Skill 智能解析与资产管理桌面工具，并提供完整会话预览、下载、删除和 Token 使用洞察。

产品首先解决“看不见、看不懂、分不清”，随后解决“安全管理”，最后补充“使用情况可见”。AI 不是事实提取器，而是建立在确定性解析结果之上的解释层。

首个版本优先建立可靠的数据模型和安全边界；会话删除作为 M3 能力，必须具备影响预览、备份、回滚和恢复。

## 2. 背景与问题

### 2.1 Skill 发现分散

Codex Skill 可以来自用户目录、仓库目录、系统能力和 Plugin。当前用户缺少统一视图，无法确认：

- 当前有哪些 Skill
- 哪些 Skill 会在当前仓库生效
- Skill 来自哪里
- Skill 是否允许修改
- 同名 Skill 是否是同一个安装

### 2.2 Skill 说明不适合人类决策

单独阅读 `name`、`description` 和完整 SKILL.md，仍难快速回答：

- 这个 Skill 实际会做什么
- 用户应该怎么说才能触发
- 它不适合什么场景
- 是否需要工具、网络、脚本或配置
- 是否会修改文件或调用外部系统
- 与相似 Skill 有什么差异

### 2.3 管理操作缺少来源与安全边界

没有安装来源凭据时，应用无法可靠判断：

- 是否存在新版本
- 更新目标来自哪里
- 覆盖后能否恢复
- 当前安装是否被用户手动修改

### 2.4 会话与 Token 数据缺少可见性

Codex 本地状态库包含会话、项目、模型、来源和总 Token 等信息，但字段和值域会随版本变化。用户需要的是使用趋势和高消耗定位，不是账单级计费。

## 3. 目标用户

### 3.1 主要用户

Codex 深度用户：

- 安装多个 Skill
- 在多个仓库工作
- 需要快速选择合适 Skill
- 关注来源、安全和维护成本

### 3.2 次要用户

Codex 新用户：

- 不熟悉 Skill 触发机制
- 希望通过中文示例理解如何使用
- 需要明确的风险和前置条件

### 3.3 团队 Skill 维护者

- 在仓库维护 `.agents/skills`
- 需要检查说明质量、依赖和重复能力
- 希望对 Skill 进行结构化审阅

## 4. 产品目标

### GOAL-1：3 秒内看见 Skill 全貌

- 应用打开后 3 秒内展示已发现 Skill，不等待 AI。
- 列表明确显示 Provider、作用域、状态和可操作能力。
- 同名 Skill 不合并，不以名称作为唯一标识。

### GOAL-2：让用户能够基于证据理解 Skill

- 每个有效 Skill 生成 Skill 护照。
- 护照包含用途、触发示例、流程、依赖、风险和证据。
- AI 不可用时仍展示确定性解析结果和原文。

### GOAL-3：仅在来源和权限明确时管理 Skill

- 所有写操作经过预检计划、用户确认和后端执行。
- 默认使用 quarantine 隔离，不直接永久删除。
- 系统、Repo、Plugin 和 Bundled Skill 默认只读。

### GOAL-4：提供完整且可管理的 Codex 会话体验

- 完整展示用户和助手之间的每一条可见对话。
- 支持下载原始 rollout JSONL。
- 支持安全删除并从 Codex-O 会话回收站恢复。
- 保留原始来源和模型值。
- 不将总 Token 伪装为输入/输出拆分或账单金额。

## 5. 核心用户故事

### US-1：查看当前有效 Skill

> 作为 Codex 用户，我希望看到不同来源和作用域的全部 Skill，以便知道当前有哪些能力可用。

验收：

- 展示 User、Repo、System、Plugin、Bundled 和 Additional Root。
- 每项展示名称、简要作用、Provider、作用域和状态。
- 同名不同路径的 Skill 分别展示。
- 单个损坏 Skill 不阻塞其他结果。

### US-2：理解某个 Skill

> 作为第一次接触某个 Skill 的用户，我希望看到可追溯的中文说明，以便知道它是否适合当前任务。

验收：

- 展示 Skill 护照。
- 至少包含一句话作用、3 个触发示例、适用场景、不适用场景、前置条件和风险。
- 事实性字段可跳转到对应文件和行号。
- 信息不足时明确标注，不编造。

### US-3：比较相似 Skill

> 作为安装多个同类 Skill 的用户，我希望并排比较它们的差异，以便选择最合适的一个。

验收：

- 支持从详情页选择另一个 Skill 比较。
- 比较用途、触发方式、依赖、工作流、风险和 Provider。
- 差异来自已有护照和静态信息，不要求每次重新调用 AI。

### US-4：安全导入和隔离 Skill

> 作为用户，我希望导入新的 User Skill，并在不确定是否需要时先隔离而不是直接删除。

验收：

- 导入前验证目录结构和 frontmatter。
- 后端生成目标路径和影响范围。
- 同名冲突不直接覆盖。
- 隔离后支持恢复。
- 系统和只读 Provider 不显示写操作。

### US-5：检查来源明确的 Skill 更新

> 作为用户，我希望只对来源可追溯的 Skill 检查更新，以免从错误来源覆盖本地内容。

验收：

- 只有存在 InstallReceipt 时显示更新状态。
- 展示来源、当前 commit/hash、目标 commit/hash。
- 检测本地修改并阻止无提示覆盖。
- 更新失败可以恢复原快照。

### US-6：查看 Codex 会话

> 作为 Codex 深度用户，我希望按项目浏览和搜索会话，并预览用户与助手的全部对话，以便完整回顾过去的工作记录。

验收：

- 自动发现可兼容的 `state_*.sqlite`。
- 按项目分组展示标题、时间、原始模型、归一化来源和总 Token。
- 详情页按 JSONL 顺序展示所有用户消息和助手消息。
- 助手消息区分过程更新和最终回答。
- 支持下载未经修改的原始 rollout JSONL。
- 支持预览删除影响、删除会话和从回收站恢复。
- 默认不展示 developer、reasoning 和 tool call。

### US-7：分析 Token 使用

> 作为用户，我希望了解 Token 消耗集中在哪里，以便识别高消耗项目和会话。

验收：

- 展示累计 Token、会话数、平均值、最大会话和时间趋势。
- 支持按项目、模型、来源和时间分组。
- Subagent 来源单独识别。
- 导出包含快照时间和统计口径。

## 6. 功能需求

### 6.1 P0：M1 看见与看懂

### P0-01 Provider 发现

发现以下 Skill 来源：

- `~/.agents/skills`
- 当前仓库 `.agents/skills`
- Codex-O 兼容配置中的历史或附加目录
- System、Plugin 和 Bundled 目录适配器

要求：

- Provider 声明读写能力。
- 目录不存在时返回空状态。
- 拒绝符号链接逃逸。
- 扫描根目录可配置但默认只读。

### P0-02 确定性 Skill 解析

解析：

- SKILL.md frontmatter
- Markdown 标题结构
- `agents/openai.yaml`
- scripts/references/assets
- 文件引用、命令示例和前置配置

要求：

- YAML 使用标准解析器。
- 单文件默认读取上限 1 MiB。
- 解析失败产生 diagnostics，不丢弃 Skill。

### P0-03 Skill 列表

列表展示：

- 名称
- 静态或 AI 摘要
- Provider 和作用域
- 有效性
- AI 分析状态
- 只读/可管理状态

支持：

- 名称和内容搜索
- Provider、作用域、状态筛选
- 名称、更新时间、文件大小排序

### P0-04 Skill 护照

护照字段：

- 一句话作用
- 能力列表
- 触发示例
- 适用与不适用场景
- 执行流程
- 前置条件
- 资源清单
- 副作用和风险
- 置信度
- 证据

### P0-05 AI 解释

支持：

- OpenAI 兼容接口
- Anthropic
- Ollama

要求：

- 输出使用 JSON Schema。
- Skill 内容按不可信数据处理。
- 调用前脱敏明显凭据。
- 用户可以查看本次发送范围。
- 失败后回退静态摘要。

### P0-06 分析缓存

缓存身份包括：

```text
content_hash
parser_version
prompt_version
schema_version
provider
model
language
```

模型、Prompt 或解析器变化后，旧结果标记为 stale，不静默复用。

### P0-07 Skill 详情与证据

- 展示 Skill 护照。
- 展示原始 description。
- 展示资源树和静态 diagnostics。
- 按需读取 SKILL.md 原文。
- 证据链接定位到文件与行号。

### P0-08 Skill 对比

- 用户手动选择 2 个 Skill。
- 并排展示护照字段。
- 高亮差异。
- 不依赖向量数据库。

### P0-09 设置与环境健康

- AI Provider 配置
- API Key 系统安全存储
- 扫描根目录配置
- 隐私模式
- Codex 数据源兼容状态
- 测试 AI 连接

---

### 6.2 P1：M2 可控管理

### P1-01 本地导入

- 支持选择 SKILL.md 或 Skill 目录。
- 验证名称、描述、文件数量、单文件大小和路径。
- 目标固定为受管 User Provider。
- 导入成功后生成 InstallReceipt。

### P1-02 Quarantine 与恢复

- 预检展示将移动的文件。
- 移动到 `~/.codex/codex-o/quarantine/`。
- 保留原位置、内容 hash 和操作时间。
- 支持恢复到原位置。
- 永久删除只针对 quarantine 内容。

### P1-03 GitHub 安装

- 支持公开仓库 URL 和子目录。
- 先下载到 Codex-O 临时目录。
- 完成静态验证和安装预览后再执行。
- 记录 URL、ref、commit SHA 和 subdirectory。

### P1-04 市场浏览与安装

- 市场是 Provider，不假定固定 JSON 字段永远存在。
- 本地缓存缺失时展示可恢复空状态。
- 安装最终复用 P1-03 的下载、验证和凭据流程。

### P1-05 更新检查

- 仅检查存在 InstallReceipt 的 Skill。
- 比较来源 ref/commit 和本地 hash。
- 本地有未记录修改时标记 conflict。
- 不用 frontmatter version 作为唯一依据。

### P1-06 安全更新

- 更新前生成备份快照。
- 展示变更摘要。
- 更新成功后触发重新扫描和分析。
- 失败时回滚。

---

### 6.3 P2：M3 会话管理与使用洞察

### P2-01 Codex 状态库发现

- 支持配置路径。
- 自动寻找可用的 `state_*.sqlite`。
- 用 `PRAGMA table_info` 检测能力。
- 只读连接，不执行迁移。

### P2-02 会话列表和详情

- 按 cwd 归一化项目。
- 展示原始模型和归一化来源。
- 支持时间、Token、项目筛选。
- rollout 路径不直接返回前端。

### P2-03 完整对话预览

- 流式读取 rollout JSONL。
- 优先解析 `event_msg.user_message` 和 `event_msg.agent_message`。
- 缺少 event_msg 时回退 `response_item.message`。
- 展示用户和助手全部可见消息。
- 保留助手 commentary/final_answer 阶段。
- 默认隐藏 developer、reasoning、tool call 和 tool output。
- 支持超长会话分段加载和虚拟滚动。
- 无效 JSON 行形成 warning，不阻断其他消息。

### P2-04 原始会话下载

- 通过系统保存对话框导出原始 rollout JSONL。
- 下载内容与源文件字节一致。
- 后端根据 session ID 解析路径，前端不传入源路径。
- 路径必须位于已允许的 sessions 或 archived_sessions 根目录。

### P2-05 安全删除与恢复

- 删除前展示 rollout 大小、最后更新时间和关联 Subagent。
- 检查 `threads`、`thread_dynamic_tools`、`thread_spawn_edges` 和未来关联表。
- schema 不支持或存在未知关联表时禁用删除。
- 最近仍在更新的会话禁止删除。
- rollout 文件和数据库行先备份到 Codex-O 会话回收站。
- 在 SQLite 事务中删除关联行和 threads 主记录。
- 删除失败时恢复文件并回滚。
- 支持从回收站恢复。
- 永久清理只针对回收站内容。

### P2-06 会话搜索

- 首版搜索 title、preview 和 first_user_message。
- 字段不存在时自动降级。
- 已加载的完整对话支持页内关键词搜索。
- 全局 rollout 全文索引不在 M3 范围。

### P2-07 Token 统计

- 使用 `threads.tokens_used` 总量。
- 不推导输入/输出/缓存/Reasoning。
- 模型名无法识别时保留原值。
- 来源归一化规则可版本化。

### P2-08 快照与导出

- 生成只读 SQLite 快照或一致性查询快照。
- CSV 使用 UTF-8 BOM。
- JSON 保留原始字段和归一化字段。
- 导出附带生成时间、数据库 fingerprint 和查询口径。

## 8. 核心体验规则

### 8.1 首次打开

1. 立即发现 Provider。
2. 3 秒内展示静态 Skill 列表。
3. 后台完成结构化解析。
4. 已配置 AI 时逐项生成护照。
5. 未配置 AI 时展示静态摘要和配置入口。

### 8.2 AI 透明度

用户可以看到：

- 使用的 Provider 和模型
- 分析时间
- 是否命中缓存
- 是否为 stale
- 发送了哪些文件范围
- 哪些结论缺少证据

### 8.3 写操作

所有写操作：

```text
预检计划 -> 展示影响 -> 用户确认 -> 后端再次校验 -> 执行 -> 验证 -> 记录结果
```

确认令牌必须绑定：

- 操作类型
- Skill ID
- 当前 content hash
- 目标位置
- 过期时间

## 9. 隐私与安全需求

- API Key 不进入普通 SQLite、日志或前端读取接口。
- 默认不把完整 Skill 目录发送给 AI。
- 不发送 assets 二进制内容。
- scripts 默认只发送摘要和选定片段。
- 明显密钥和 Authorization 值发送前脱敏。
- 日志不记录 Prompt、AI 原始响应、Skill 正文或会话正文。
- 会话正文只在本机解析，不发送到 Skill AI 服务。
- Codex 状态库常规查询只读；删除通过独立受控写入连接。
- 所有路径在 Rust 层规范化并做根目录约束。

## 11. Non-goals

- 不替代 Codex。
- 不执行 Skill。
- 不编辑 Skill 正文。
- 不修改 Repo、System、Plugin 或 Bundled Skill。
- 不修改会话内容。
- 不展示内部 reasoning、developer 指令和工具事件为普通对话。
- 不直接永久删除活跃会话。
- 不实现会话归档或压缩。
- 不提供账单级费用估算。
- 不自建云端 Skill 市场。
- 不上传会话内容。
- 不承诺支持未公开内部格式的永久兼容。

## 14. 官方能力依据

- Codex Skill 是 `SKILL.md` 加可选 scripts/references/assets 的可复用工作流。
- Codex 使用 metadata -> SKILL.md -> resources 的渐进式加载。
- 全局 Skill 当前使用 `~/.agents/skills`，仓库 Skill 使用 `.agents/skills`。
- Plugin 是 Skill 的可安装分发单元之一。

参考：`https://learn.chatgpt.com/docs/customization/overview#skills`
