# Codex-O 原型目录 AI 规范

本文件适用于 `prototype/` 下的全部文件，是根目录 `../AGENTS.md` 的局部补充。发生冲突时，
先遵守根目录规范和 `../doc/产品蓝图与领域模型.md`。

## 1. 目录决策

- `prototype/` 是完整、可独立打开的原型交付包，保持现有目录结构。
- `README.md`、`BRIEF.md`、`DESIGN.md`、`index.html`、`pages/` 和 `assets/` 不移出本目录。
- 保留相对链接、离线打开能力和 1280×800 桌面窗口基准。
- `../prototype.zip` 位于项目根目录，是导出物，不因普通原型修改自动更新。

移动这些文件会破坏相对链接、评审入口和交付包边界，因此除非用户明确要求重组原型，
不得移动、改名或拆分。

## 2. 阅读顺序

修改原型前按顺序阅读：

1. `../AGENTS.md`：项目级流程、安全边界和进度要求。
2. `../doc/产品蓝图与领域模型.md`：当前产品范围和阶段边界。
3. `../doc/需求文档.md`：当前正式需求与验收指标。
4. `BRIEF.md`：原型生成时使用的需求摘要。
5. `DESIGN.md`：原型设计令牌和视觉规范。
6. `README.md`：页面结构、交互入口和已知遗留。
7. 目标页面及其共享 `assets/`。

`BRIEF.md` 是原型过程文档，不是新版 PRD。它与 `../doc/` 冲突时以 `../doc/` 为准，
并同步修正受影响的原型说明，禁止让旧原型描述反向改变产品范围。

## 3. 文件职责

| 文件或目录 | 职责 | 修改要求 |
|---|---|---|
| `README.md` | 原型交付说明、页面清单和评审入口 | 页面、交互或验证结果变化时同步更新 |
| `BRIEF.md` | 原型需求摘要和示例数据 | 只在原型范围变化时更新，不代替正式 PRD |
| `DESIGN.md` | 原型设计令牌与视觉规则 | 设计系统变化时先改规范，再改 CSS |
| `index.html` | 9 页评审入口，不是正式产品页 | 页面清单或演示能力变化时同步更新 |
| `pages/*.html` | 9 个产品页面原型 | 保持页面头部 PRD/状态注释准确 |
| `assets/tokens.css` | 设计令牌实现 | 与 `DESIGN.md` 保持一致 |
| `assets/app.css` | 全局组件和布局 | 修改前评估全部 10 个 HTML |
| `assets/icons.js` | 共享图标库 | 保持 24×24、stroke 风格和统一注入方式 |
| `assets/app.js` | PROTO 工具条和共享交互 | 不承载正式业务逻辑 |

## 4. 原型修改规则

- 原型使用纯 HTML、CSS 和 vanilla JS，保持零构建、零 CDN、零外部字体、零网络请求。
- 现有 9 页信息架构必须保留；新增或删除页面需要先修改正式产品文档。
- 页面中的 PROTO 工具条只用于评审，不得当成正式产品 UI。
- 原型可以模拟加载、空态、错误和降级，但未启用能力不得模拟真实操作成功。
- 危险操作必须展示影响范围并默认聚焦取消按钮。
- UI 文案使用中文，技术术语保留英文。
- 不使用 lorem ipsum；示例数据必须符合产品领域。
- 共享能力优先修改 `assets/`，页面专属布局和交互留在对应页面。
- 修改 `assets/` 前必须检查全部页面影响，不得只验证当前页面。
- 修改页面功能后同步更新：
  1. 页面头部覆盖清单。
  2. `README.md` 页面与功能点对照。
  3. `index.html` 对应评审卡片和全局弹窗清单。
  4. 根目录 `../PROGRESS.md` 的步骤记录。

## 5. 正式应用如何使用原型

正式 Tauri/React 实现可以复用：

- 9 页信息架构和导航关系。
- `DESIGN.md` 与 `tokens.css` 的令牌语义。
- 页面状态、弹窗流程和信息层级。
- 已经对齐新版 PRD 的中文文案。

正式实现不得直接复用：

- PROTO 工具条。
- 页面内模拟成功逻辑。
- 静态示例数据。
- 直接读写 DOM 的 vanilla JS。
- 前端保存的绝对路径、密钥或 confirmation token。
- 与正式领域模型、Provider 权限或 IPC 契约冲突的旧原型行为。

React 组件必须根据正式数据模型和 IPC 契约重新实现。权限和安全判断由 Rust 后端负责，
不能因为原型有按钮就在前端启用能力。

## 6. 验证要求

原型改动完成后至少验证：

1. 全部 HTML 的本地 `href`、`src` 没有死链。
2. HTML `id` 不重复。
3. 共享 JS 和全部内联 JS 语法正确。
4. 目标页面在 1280×800 下无重叠、横向溢出和文字截断。
5. 修改共享资产时抽查全部 9 个产品页面。
6. 弹窗、空态、错误态、AI 降级态和返回入口仍可用。
7. `README.md`、页面头部注释和实际页面能力一致。

验证结果必须写入根目录 `../PROGRESS.md`，并按根规范输出步骤总结。只看源代码、不做页面
渲染检查，不得标记原型任务完成。
